nest 接入申请

申请把一台设备或一个 agent 接入 nest 技能库与日志库。

接入分两步：你在自己机器上生成一把钥匙并提交公钥，由管理员人工核对后批准。私钥永远不要离开你的机器，也不要贴到这个页面上。

提交不等于获批。提交后你会拿到一串指纹，你需要通过另一个渠道（当面、聊天工具、对话）把这串指纹告知管理员。管理员会核对两边是否一致，对不上不予批准 —— 这样即使这个页面的密码泄露，冒名提交也进不来。

1. 生成钥匙

只接受 ed25519 类型。在你自己的机器上执行：

ssh-keygen -t ed25519 -f ~/.ssh/nest_key -N "" -C "改成你的标识"
cat ~/.ssh/nest_key.pub

最后一条命令输出的那一行就是公钥，可以公开。~/.ssh/nest_key（没有 .pub 后缀的那个）是私钥，任何情况下都不要发给别人。

2. 提交申请

如果你是 agent 或习惯命令行：

python3 - <<'PY' > /tmp/nest-req.json
import json, pathlib
print(json.dumps({
    "name": "agent-b",          # 2-32 位，只能用字母数字 . _ -
    "pubkey": pathlib.Path("~/.ssh/nest_key.pub").expanduser().read_text().strip(),
    "note": "内网部署机，需要读写"
}, ensure_ascii=False))
PY

curl -sS --user '<用户名>' \
     -H 'Content-Type: application/json' \
     --data-binary @/tmp/nest-req.json \
     https://nest.example.com/enroll/api/request

返回的 JSON 里有 id（查询进度用）和 fingerprint（需要你转告管理员的指纹）。

如果你是人，用下面的表单：

2-32 位，字母、数字、点、下划线、连字符。这个名字会成为吊销时的凭据。

粘贴 ~/.ssh/nest_key.pub 的完整内容。确认开头是 ssh-ed25519。

3. 转告指纹

提交成功后你会看到一串形如 SHA256:xxxxx… 的指纹。通过另一个渠道把它发给管理员。管理员那边会执行核对，两边指纹一致才会批准。

4. 查询进度

curl -sS --user '<用户名>' \
     https://nest.example.com/enroll/api/status/<你的id>

状态变成 approved 后继续下一步。

5. 验证钥匙并安装

不要改 ~/.ssh/config。同一台机器上可能有别的 agent 也在用 nest， 多个同名 Host 块会让 SSH 把各自的 IdentityFile 累积起来按顺序尝试， 排在前面的别人的钥匙一旦有效就被采用 —— clone 会"成功"，但用的是别人的身份。 用 -i 直接指定自己的钥匙：

ssh -i ~/.ssh/nest_key -o IdentitiesOnly=yes git@nest.example.com

看到 fatal: Interactive git shell is not enabled. 就是成功了。这个账号被刻意限制成只能收发仓库，进不了 shell，所以拒绝交互式登录是预期行为。

如果看到 Permission denied (publickey)，说明还没批准，或者用错了钥匙。

然后一键安装（脚本会把你的钥匙固定为仓库级 core.sshCommand，不碰 ~/.ssh/config）：

curl -sS --user '<用户名>' https://nest.example.com/install.sh -o /tmp/nest-install.sh
bash /tmp/nest-install.sh \
  --repo git@nest.example.com:/srv/git/nest-sync.git \
  --key ~/.ssh/nest_key --name agent-b -y
echo 'export PATH="$HOME/.nest/bin:$PATH"' >> ~/.bashrc && source ~/.bashrc

6. 验证

nest status
nest recall <项目名>

能看到同步状态和日志内容，就装好了。

7. 日常命令

命令什么时候用
nest pull开工前，拉云端最新
nest push -m "说明"收工后，回传本地改动
nest recall <项目名>唤回项目日志。只读，本地有未提交改动时照样能用
nest status看本地和云端差在哪

第一阶段全部手动触发，不挂自动 hook。

8. 红线

以下内容绝不能提交进这个仓库：API key、token、密码、证书私钥、个人隐私资料。

仓库有两道自动闸门（本地提交时扫一次，服务端接收时再扫一次），但闸门只认已知格式，不替代判断。项目日志涉及真实主体时一律用 [项目A] 这类代号。

判断标准：只放"丢了会心疼但不致命"的东西。

钥匙丢了或设备不再使用，立刻告诉管理员吊销 —— 报你当初提交的标识即可。
