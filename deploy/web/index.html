如果你是 agent

本页有一份等价的纯文本版，更适合你直接读取和执行（整站需认证）：

curl -sS --user '<用户名>' https://nest.example.com/nest.md

先跑这一句判断本机状态，再决定走哪条路：

command -v nest >/dev/null 2>&1 && nest status || echo "NOT_INSTALLED"

这是什么

所有设备、所有 harness（Claude Code、Codex、Kimi Code 等）共享同一份内容：

  • 技能库 —— 工作方法论。任一端更新，回传后其他端立即生效
  • 日志库 —— 项目进度、复盘、配置备忘录。可按项目名唤回，不必手动翻找复制粘贴

底层是一个托管在自己服务器上的 Git 仓库，它是唯一权威。所有命令都只是它的包装。

怎么接入

需要管理员人工批准。除第 2 步和第 4 步外都可以自动完成。

  1. 生成钥匙 —— ssh-keygen -t ed25519 -f ~/.ssh/nest_key，只接受 ed25519
  2. 向管理员索取访问凭证 —— 本站整站需要认证，凭证不公开
  3. 提交公钥 —— 标识自选但不可与已有条目重名，拿到申请编号和指纹
  4. 把指纹报给管理员 —— 核对无误后批准
  5. 配置 SSH 并克隆 —— 跑 install.sh 完成全部初始化
  6. 验证 —— nest status 和 nest recall <项目名>

完整命令见纯文本版。

第 4 步不能跳过。申请页面的密码是共享的，只能挡住扫描器；真正拦住冒名提交的， 是管理员拿你报的指纹和服务器上收到的申请做的那次核对。两边对不上就不会批准。

接入完成后，nest 技能会自动安装到你的 harness 技能目录（软链到仓库，随仓库更新）。 以后关于 nest 的任何用法直接查那个技能，不必再回到本页。

日常使用

命令用途
nest pull开工前，拉云端最新并重建技能软链
nest push -m "说明"收工后，回传本地改动
nest recall <项目名>唤回项目日志。纯只读，工作区有未提交改动时照样能用
nest status看本地与云端差在哪

技能真身在 ~/.nest/git/skills/，各 harness 目录是软链过去的。 直接改真身，所有 harness 立即生效。绝不要维护第二份副本。

红线

绝不能提交进这个仓库：API key、token、密码、证书私钥、个人隐私资料。

仓库有两道自动扫描闸门，但闸门只认已知格式，不替代判断。日志涉及真实主体时一律用 [项目A] 这类代号。判断标准：只放"丢了会心疼但不致命"的东西。

接入遇到问题直接问管理员。钥匙丢失或设备停用，立刻联系吊销 —— 报当初提交的标识即可。
