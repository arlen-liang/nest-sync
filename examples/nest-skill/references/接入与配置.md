# nest 接入与配置

**这个文件只在装机、换 harness、调身份时需要读。** 日常使用（pull / push / sync /
recall / bind）不需要它，见 `SKILL.md`。

从 SKILL.md 拆出，理由是这几块内容一台机器只需做一次，却在每次唤起技能时占掉大量正文
—— 典型的高频载入、低频使用。拆分规则本身见 `SKILL.md` 的「内容组织」一节。

---

## 从零接入

### 情况一：这台机器已经有人在用 nest，只是当前 harness 没接上

```bash
nest link
```

自动识别本机装了哪些 harness（默认查 `.claude` / `.kimi-code` / `.codex`），
只往**已存在**的目录建软链。完事。装了别的 harness 用 `NEST_LINK_TARGETS` 显式指定。

### 情况二：全新机器，从头装

需要管理员在服务端批准，无法自助完成。按顺序做，第 3 步必须等回复。

**1. 生成钥匙**（只接受 ed25519）

```bash
ssh-keygen -t ed25519 -f ~/.ssh/nest_key -N "" -C "这台机器的标识"
```

私钥 `~/.ssh/nest_key` 永远不要发给任何人。

**2. 提交接入申请**

接入说明页与提交接口都需要一组用户名密码，**向管理员索取**（凭证不存在仓库里）。
拿到后可以先读一遍纯文本版说明：

```bash
curl -sS -u '<用户名>:<密码>' https://nest.example.com/nest.md
```

提交申请：

```bash
python3 - <<'PY' > /tmp/nest-req.json
import json, pathlib
print(json.dumps({
    "name": "改成这台机器的标识",   # 2-32 位，只能用字母数字 . _ -；见下方命名规则
    "pubkey": pathlib.Path("~/.ssh/nest_key.pub").expanduser().read_text().strip(),
    "note": "哪台机器，做什么用"
}, ensure_ascii=False))
PY

curl -sS -u '<用户名>:<密码>' \
     -H 'Content-Type: application/json' \
     --data-binary @/tmp/nest-req.json \
     https://nest.example.com/enroll/api/request
```

**命名规则**：`name` 由自己选，系统不核实，但它是**吊销时的唯一凭据**，且**不允许与
名单中已有条目重名**（重名会导致吊销时无法区分，批准环节会直接拒绝）。
用能唯一标识这台机器的名字，例如 `agent-b`、`dev-laptop`。

**3. 把返回的 fingerprint 报给管理员，然后等待**

返回结果里有一串形如 `SHA256:xxxxx` 的指纹。**必须通过对话直接告诉管理员**，
管理员会拿它和服务器上收到的申请核对，两边一致才批准。

这一步不能跳过，也不能让管理员自己去页面上抄指纹 —— 那样核对就失去意义了。
在管理员明确说"已批准"之前，下面的步骤做不了。

查询进度：

```bash
curl -sS -u '<用户名>:<密码>' https://nest.example.com/enroll/api/status/<你的id>
```

**4. 验证钥匙可用 —— 不要改 `~/.ssh/config`**

同一台机器上可能有别的 agent 也在用 nest。`~/.ssh/config` 里出现多个同名 `Host` 块时，
SSH 会把所有 `IdentityFile` 累积起来按顺序尝试，排在前面的**别人的钥匙**一旦有效就被
采用 —— clone 会"成功"，但用的是别人的身份，而且不会有任何报错。

直接指定自己的钥匙：

```bash
ssh -i ~/.ssh/nest_key -o IdentitiesOnly=yes git@nest.example.com
```

看到下面两行**就是成功了**：

```
fatal: Interactive git shell is not enabled.
hint: ~/git-shell-commands should exist and have read and execute access.
```

这个账号被刻意限制成只能收发仓库：进不了 shell、不能 sudo、不能端口转发、不给伪终端，
登录时也不打印任何系统信息。拒绝交互式登录是预期行为，不是出错。
看到 `Permission denied (publickey)` 说明还没批准或钥匙路径写错了。

**5. 安装（一条命令，脚本自己探索与确认）**

```bash
curl -sS -u '<用户名>:<密码>' https://nest.example.com/install.sh -o /tmp/nest-install.sh
bash /tmp/nest-install.sh \
  --repo git@nest.example.com:/srv/git/nest-sync.git \
  --key ~/.ssh/nest_key --name <你的标识> -y
```

脚本顺序固定：**先本地探索**已有仓库（找到就指给你复用，拒绝重复克隆）→ 没有才显示
克隆目标的**绝对地址**（死约定 `~/.nest/git`，与当前目录无关）→ 确认后克隆。
`--key` 固定为仓库级 `core.sshCommand`，`--name` 写成仓库级提交身份，
非交互环境 `-y` 表示"地址已确认"。

确要独立另装一份时才用 `NEST_HOME=~/.nest-你的标识` 前缀 —— 显式设置视为刻意行为，
探索闸放行。

`install.sh` 会装密钥扫描 hook、设中文路径显示、装 `nest` 命令、自动识别 harness 建立
软链，最后**打印本仓库实际使用的钥匙指纹** —— 核对是不是你自己那把。
按它给出的提示把 `nest` 加进 PATH。

**6. 验证**

```bash
nest status
nest recall <项目名>
```

两条都有正常输出即安装成功。

## 同一台机器上有多个 agent

这台机器可能同时住着好几个 agent（各自有独立身份和钥匙）。两种做法：

**推荐：共用一份 `~/.nest/`。** 技能和日志本来就该是同一份，没有分家的理由。
后接入的 agent 只需 `nest link` 把技能挂到自己的 harness 目录，不必重新 clone。

**若必须各装各的**（例如要验证独立身份），装到不同 `NEST_HOME`：

```bash
NEST_HOME=~/.nest-你的标识 bash <仓库>/install.sh
```

注意两点：

- `nest` 命令会**从自身位置反推所属仓库**，所以不需要在 shell 里持久化 `NEST_HOME`；
  调用 `~/.nest-你的标识/bin/nest` 操作的就是你自己那份
- 各 harness 的技能目录只能有一份软链。先到先得，后来者的 `nest link` 会**跳过并说明**
  已有软链属于谁，不会覆盖。如果不想参与软链，装的时候加 `--no-link`

## 身份与追溯（谁改了什么）

每个访问者 —— 人也好、agent 也好 —— 都用**独立的 git 身份 + 独立钥匙**，不混用。
这样 `git log` 的提交署名、服务端的 SSH 审计日志都能追溯到每一次改动是谁做的。

- 身份 = 仓库的 `user.name/email`（提交署名）+ `core.sshCommand`（连接钥匙），两样都独立
- 一把钥匙只属于一个身份：agent 的钥匙不给人用，人的钥匙也不给 agent 用
- 切换身份 = 改仓库 `user.name/email` + `core.sshCommand`，而不是共用一把钥匙只改署名

**实例**（同一台服务器上人和 agent 各一套）：

| 身份 | 谁 | 钥匙（core.sshCommand） | git 署名 |
|---|---|---|---|
| `agent-b` | 常驻 agent，日常维护 | `~/.ssh/nest_agent_key`（授权名 `nest:agent-b`） | `agent-b <agent-b@nest.local>` |
| `alice` | 管理员本人，手动操作 | `~/.ssh/nest_deploy_key`（授权名 `nest:alice`） | `alice <alice@nest.local>` |

不要一把钥匙兼两职。真要这么做，等于放弃了审计时的"谁做的"这一信息。

## 选择性拉取技能大类

仓库全量同步，但每台设备可以只把需要的大类挂进 harness。在 `~/.nest/config` 写：

```bash
NEST_LINK_CATEGORIES="meta work"     # 工作机
NEST_LINK_CATEGORIES="meta personal" # 个人设备
```

不设 = 全拉。改动后跑 `nest link`，取消勾选的大类的软链会被移除。
`meta` 建议永远保留 —— nest 自己的使用说明在里面。
